## 二、先确定整体综述的科研问题（建议三问）

- **RQ1：图谱如何构建？** 从实体三元组、跨文档段落关系图到文本属性图，节点/边语义、来源约束和构建质量有何不同？
- **RQ2：图谱如何检索与推理？** 图遍历 Agent、PCST 子图选择、社区级搜索、PPR 传播分别优化什么，时间/成本/准确率怎样权衡？
- **RQ3：图结构如何支持知识的持续复用？** 在图谱与原始段落之间如何保留上下文，并为多跳关联提供可追溯证据？HippoRAG 2 仅作为这一问题的应用例子。

**技术递进**：SAC-KG（三元组图的生成和校验）→ KGP（段落/结构关系图上的逐步检索）→ G-Retriever（文本属性图的子图优化检索）→ FastToG（KG 上的社区级推理）→ HippoRAG 2（关系图与段落索引结合支持长期知识利用）。

注意：这是课程报告的**逻辑组织顺序**，不意味着后论文直接继承前一篇或构成同一技术谱系。

## 三、五篇论文的定向精读与翻译重点

### 01 SAC-KG｜构建可信领域知识图谱｜16 页
**论文实际任务**：在领域文本上生成多层实体关系三元组；解决领域噪声、知识幻觉和扩展控制。
- 机制必须讲清：Generator（检索领域文本与开放知识）→ Verifier（检测/纠错生成三元组）→ Pruner（判定哪些尾实体进一步扩展），循环形成图。
- 推荐保留原图：**Figure 2** 全流程；至少核验 **Table 1** 中 precision、domain specificity 和 backbone 选择。
- 评价重点：论文报告 ChatGPT 作为骨干时 precision **89.32%**，只在其构建评测口径下讨论，不能与问答准确率并列比较。
- 阅读问题：验证依赖规则和通用 KG 会引入哪些偏差？图谱的来源证据与错误传播如何控制？

### 02 KGP｜跨文档段落关系图与遍历 Agent｜22 页
**论文实际任务**：跨多文档问答，知识图上的节点并不全是实体，主要是 **passage/page/table** 等，边体现词汇/语义相似性或文档结构归属。
- 机制必须讲清：文档切分、TF-IDF / KNN / MDR 等建图方式、结构节点；LLM 图遍历 Agent 按问题逐步找证据，可通过指令微调。
- 推荐重点：**Figure 3** 图构建、**Figure 4** 遍历 Agent，相关问答与检索消融表；关注 2WikiMQA / MuSiQue 多文档问题与检索延迟。
- **特别提醒**：仓库是 22 页作者版，附录/补充讨论不能因公开 AAAI 主会仅 9 页而被误删。
- 阅读问题：由相似性连接的 passage graph 与真实语义三元组 KG 有什么本质差异？遍历对图结构质量有多敏感？

### 03 G-Retriever｜文本属性图上的 GraphRAG｜32 页
**论文实际任务**：让 LLM 对文本属性图回答问题并给出相关图结构依据；不只适用于传统 KG。
- 机制必须讲清：Indexing → node/edge retrieval → **Prize-Collecting Steiner Tree (PCST)** 选连通子图 → 图/文本编码与答案生成。
- 重点图表：**Figure 3** 方法；**Table 3** 结果；**Table 4** Token / 节点 / 训练效率；附录 **Table 10** 比较 PCST、Top-k triples、Top-k nodes、最短路径。
- 论文附录报告在 WebQSP 的特定设置下 PCST Hit@1 = **66.17**，Top-k triples = **52.64**；这只是该表同设置下的比较，不作跨论文直接排名。
- 阅读问题：PCST 的 prize/cost 由什么决定？如何控制子图体积、保持证据连通并减少无关上下文？32 页中大段附录需安排专门译审。

### 04 FastToG｜社区级知识图谱多跳推理｜11 页
**论文实际任务**：稠密 KG 上的多跳推理成本较高，提出按社区而不是逐个孤立节点探索。
- 机制必须讲清：Local Community Search → 社区检测 → **基于 modularity 的粗剪枝 + LLM 精剪枝** → Triple2Text / Graph2Text → 推理链迭代。
- 重点：**Figure 1** 不同宽度/深度的检索比较、**Figure 2** 整体框架；实验使用 CWQ、WebQSP、QALD、ZSRE、T-REx、Creak 等不同任务数据，结果需分数据集分析。
- 阅读问题：社区聚合会节省哪些 LLM 调用？会不会丢掉跨社区短路径？参数与社区检测成本如何影响效率？
- 补充：作者版含 Appendix 的算法伪代码，全文翻译时保留。

### 05 HippoRAG 2｜以 KG 为索引的长期知识复用｜19 页（唯一 Memory）
**论文实际任务**：补足纯向量 RAG 的多跳关联能力，同时兼顾事实记忆和长上下文理解。
- 离线：LLM OpenIE 抽取 triples，短语节点之间加同义关联，再将原始 **passage nodes** 纳入同一开放 KG。
- 在线：查询关联 passages 和 triples → recognition memory 筛选三元组 → phrase/passage 种子赋权 → **Personalized PageRank** → 选段落供回答模型使用。
- 重点：**Figure 2** 离线/在线流程，**Table 2** 不同问答任务的 F1，以及后续消融表；比较 factual / associative / sense-making 三类能力。
- 阅读问题：为什么只保留实体图会丢失上下文？为什么引入段落节点？Recognition memory 和 PPR 分别解决什么？
- 不扩展 A-Mem、G-Memory、Memory-R1，确保 Memory 只占五分之一。

## 四、写作成品的组织方式

最终建议**一份装订的报告正文 + 五篇完整翻译作为独立附录或后续装订部分**，以老师最终提交口径排版：

A. **综述与个人研究（作者审定）**：
1. 选题背景与问题定义（介绍 KG/GraphRAG，不铺开 Agent Memory 综述）。
2. 五篇研究的技术主线和论文定位（区别 KG、passage graph、textual graph）。
3. 横向方法对照：图节点/边、构图方式、检索粒度、推理策略、所需 LLM 调用、评价任务、缺陷。
4. 综合讨论：图谱质量—检索精度—连通路径—推理成本的关系；提出研究问题。
5. 结合本人工作的创新设想：**可溯源图谱 + 查询自适应子图检索 + 证据链反馈**，可用自己的 RAG / Agent 长期任务作说明；Complementary RL 最多一小段展望。
6. 总结与参考文献。

B. **论文全文翻译（5 篇分开成稿）**：原英文标题、中文译文、原图与图注、表格/公式、术语表，参考文献保留英文原文。**按上传 PDF 原顺序进行翻译，不以文献分析代替原文翻译。**

### 翻译 QC 最小标准（每篇都执行）
- **完整性**：逐页记录“已翻/待翻/表图已核/附录已核”，不把 PDF 页数简单等同于正文页数。
- **术语一致**：node 节点、edge 边、triple 三元组、passage 文段、subgraph 子图、community 社区、pruning 剪枝、personalized PageRank 个性化 PageRank、recognition memory 识别记忆。
- **技术正确性**：符号、损失函数、算法步骤、训练/推理条件与实验设置不改写；“百分比”与“百分点”分清。
- **视觉与引用**：所有原图图注与表头逐项对照，图像放大后可读；按各论文原 PDF 的 Figure/Table 编号，不把作者版和主会版编号混用。
- **学术边界**：报告中的个人评判与作者原结论分开，不夸大可解释性、成本节约或模型能力。

## 八、当前风险和结论

1. **“全文翻译”的附录边界**：按保守口径翻译除参考文献外的全文和附录；若老师允许附录豁免，再节省工作量。
2. **同一主题边界**：四篇涉及 KG 构建、跨文档图、文本属性图与 KG 社区推理，材料并非完全同构。开篇先定义“知识图谱/图结构增强检索与推理”，避免把所有图一律称为经典 KG。
3. **KGP 与 FastToG 版本问题**：已上传的是 arXiv 作者版本，未来页码、图表、算法按仓库版本引用，正式会议信息按出版记录引用。
4. **交叉课程时间冲突**：网络与信息安全先于本课程截止，11-25 晚之前形成知识图谱的可打印版本更稳妥。
5. **先验结论边界**：目前不开展新实验；用户补充新研究思路后再细化技术设计；不得虚构自有实验增益。

**结论**：选文可以保留，报告应以知识图谱的“构建—检索—子图/社区推理”为主体，HippoRAG 2 只承担扩展应用的角色。下一步直接从 P1/P2 开始，不再重复改选题。
